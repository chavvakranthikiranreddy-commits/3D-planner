# Response to the Archiform application audit (1 November 2026)

This document records what was changed for each finding in the audit report, how each change is tested, and what is still open. Finding IDs (A01–A34) match the report.

**Version:** 0.2.0 · **Frontend tests:** 52 (vitest) · **Backend tests:** 16 (pytest).

Every finding the audit *reproduced* now has a regression test in `frontend/src/__tests__/audit.test.ts`, `frontend/src/__tests__/store.test.ts` or `backend/tests/`. Browser checks were run in headless Chromium with SwiftShader WebGL, at a 1500×900 desktop size and a 390×844 touch size. Those checks are listed in §4. They do **not** replace testing on real devices, in Safari/iOS, or with real users (§5).

## 1. Stage 1: protect user work

| ID | Status | What changed | Test |
|---|---|---|---|
| **A01** Autosave race | ✅ Fixed | The store keeps a monotonic `rev` (incremented on every change) and a `savedRev` (the newest revision on disk). Writes are serialised: after each write the loop checks for newer revisions, so the status only shows "saved" when `rev === savedRev`. Each save is guarded against a project switch happening mid-write. Opening a project now waits for any pending write first. | `store.test.ts › A01` holds a write, edits during it, then releases. The newest edit is persisted and the status is correct. |
| **A02** Chat widened a deletion to the whole project | ✅ Fixed | A command that names a room the chat cannot resolve (unknown, ambiguous or missing) now stops before doing anything. Removal needs an explicit scope (a room, or "whole house"). Removing more than one item first lists the item count and room names and asks for a "yes". | `audit.test.ts › A02` (3 cases) |
| **A03** Shared identity and optional auth | ✅ Mitigated for shared self-hosting | `API_TOKENS="alice:…,bob:…"` gives each token its own user id, and every query is scoped by owner. With `APP_ENV=production`, the server **refuses to start** without tokens. Local single-user mode remains an explicit choice. **Still open:** a managed identity provider (OIDC/JWT) is needed before running a public consumer service; `current_user()` is the only place that needs to change. | `test_users_are_isolated`, `test_auth_check_rejects_wrong_token` |
| **A06** Bad import broke the dashboard | ✅ Fixed | `validateScene()` checks the whole file before anything is written: floors present, every array and reference, finite and bounded numbers, embedded image sizes, and the schema version. Files from a newer schema are rejected instead of being relabelled as current. The project list isolates unreadable records: each shows as a "damaged" card with *Export raw data* and *Delete*, and the other projects still load. | `audit.test.ts › A06`; browser: an injected bad record shows as a damaged card |
| **A08** Import replacement / recovery | ✅ Fixed | The import runs as a single transaction. A **"Before import"** version is saved automatically. Geometry, blueprint reference, scale and floor height then change in **one undo step**. Blueprints now live in the scene as references, with the images stored in `project.assets`, so Undo also restores the previous underlay. Step 4 shows exactly what will be replaced and asks whether to **keep or remove existing furniture**. "Trace manually" goes through the same confirmation step. | Browser walkthrough (§4) |
| **A12** Rename/archive lost on reopen | ✅ Fixed | Opening the dashboard finishes any pending save and then drops the in-memory project, so the dashboard is the single source of truth. `openProject` reloads whenever the stored copy is newer. | `store.test.ts › A12`; browser: rename on the dashboard, reopen, new name shown |
| **A25** Backend accepted unusable scenes / returned 500 | ✅ Fixed | Nested Pydantic models check floors, walls, openings, rooms and objects: finite and bounded numbers, enums, and that floor and wall references exist. Unsupported schema versions return 422. JSON bodies larger than `MAX_JSON_MB` are rejected before parsing, and lists have size limits. | `test_scene_validation_returns_422_not_500` (6 bad payloads) |

## 2. Stage 2: make the conversion trustworthy

| ID | Status | What changed | Test |
|---|---|---|---|
| **A04** Auto threshold failed on pure black/white | ✅ Fixed (both engines) | The ink comparison is now inclusive (`<= threshold`), because Otsu returns 0 for binary drawings. Inverted sheets (light lines on dark) are detected and flipped. | TS: binary, faint, inverted, noisy and anti-aliased cases with **no explicit threshold**; Python: the same set |
| **A05** Irregular rooms became rectangles | ✅ Fixed (both engines) | Rooms are traced as outlines: boundary tracing plus Douglas–Peucker in the browser, `findContours` plus `approxPolyDP` on the server. Concave corners are kept. Irregular outlines are flagged `irregular` and highlighted for review in the wizard, and the room is generated from the polygon. | L-shaped test: polygon area within 6% of the filled area and clearly smaller than the bounding box |
| **A07** Stale scale or detection | ✅ Fixed | Changing the points, length or units after *Apply* clears the applied scale. Detection results are tied to a fingerprint of image, scale, threshold and engine; any change hides them and re-runs detection. The final step shows the reference length and sheet size. | Browser: change the length after Apply, then *Apply scale* is required again and *Next* is disabled |
| **A09** 2D/3D disagreed on opening position | ✅ Fixed | One rule (`normalizeOpening`) is applied after **every** edit and when loading old data, so the stored value is always the normalised one. 2D, 3D, walkthrough and estimates therefore read the same data. Validation also flags openings that extend past a wall end. | `audit.test.ts › A09` |
| **A10** Wall edits broke connections | ✅ Fixed | When you drag a wall end or a whole wall, or edit its length or angle, every attached wall end and room corner moves with it; these are captured once when the drag starts, so passing over other walls doesn't grab them. *Split* never cuts through a door or window and keeps per-room paint spans on both halves. **Still open:** T-junctions (a wall ending in the middle of another wall) are not yet carried along when that other wall moves. | `audit.test.ts › A10` |
| **A11** AI furniture outside rooms | ✅ Fixed | The new `placement.ts` checks that the **whole rotated footprint** is inside the real (possibly concave) room, that it doesn't overlap other furniture (separating-axis test), and that door swing zones stay clear. Wall items slide along each wall face and stand just inside the room outline. When nothing fits, the result says *"no safe spot"*. "Items in this room" now means items inside the room outline, not inside its bounding box. The design chat uses the same placement code. | `audit.test.ts › A11` (L-shaped room, plus a plan traced at inner wall faces) |
| **A13** Painting one room repainted a shared wall | ✅ Fixed | Walls carry per-face **spans** (`from–to` in metres). Room painting changes only the stretch of each face the room covers; this is found by matching wall lines to the room outline, which also gives the side. The 3D view splits wall pieces at span boundaries. | `audit.test.ts › A13` (the sample's 11 m top wall shared by the hall and master bedroom) |
| **A20** Wrong totals for same-looking items | ✅ Fixed | Products are grouped by price, brand and estimated status as well. Wall finishes are measured per face span and per material, minus openings. The currency symbol is labelled "label only — no conversion" in the UI and in the report. | `audit.test.ts › A20` (100 + 200 = 300; per-material paint lines) |

## 3. Quality, honesty, usability (P2 and first-time-user items)

| ID | Status | Notes |
|---|---|---|
| A14 Ceiling button opened Floor | ✅ | The Floor, Ceiling and "Paint this room's walls" buttons set the target. A sticky **"Applying to: Ceiling"** banner shows what will change. |
| A15 Imperial bounds / decimal feet | ✅ | Length fields take metres internally, with bounds converted correctly. Imperial projects accept `10' 6"`, `10 6`, `126"` or `10.5`, and calibration accepts feet and inches too. |
| A16 Excluded rooms couldn't be restored | ✅ | Excluded items stay visible as muted outlines and can be clicked back in. There is a review list with checkboxes and *Reset exclusions*. Counts show what is kept, and openings on excluded walls are left out. |
| A17 One blueprint per project | ✅ | Underlays and calibration are stored **per floor**. When adding a floor, exterior walls are now classified by whether one face lies outside every room (thickness is only a fallback). The UI states that stairs and moving between floors are not supported. |
| A18 Walkthrough input | ✅ | Movement only works with pointer lock or touch controls. Typing in text fields is ignored, held keys clear on blur or tab switch, and you respawn in the largest room when the floor changes. You stay on the floor (inside rooms or doorways). There is an on-screen D-pad and drag-to-look for touch. **Still open:** furniture collision. |
| A19 Old chat Undo buttons | ✅ | Each message records the undo depth after its change, so *Undo this change* only appears while it is still the latest change. Older messages point to the main Undo. |
| A21 "Cloud storage" claim | ✅ | Removed. The UI says **"Saved on this device"** and the export panel explains backups. **Still open:** syncing projects to the backend (the API exists, but the browser doesn't use it yet). |
| A22 "High quality" / Blender wording | ✅ | Renamed to **Export 3D view (PNG)**. The fake quality switch is removed, and the text states it is the real-time view, not photoreal. The export size is limited to what the GPU supports. |
| A23 Jobs not project-scoped / cancel ignored | ✅ | Jobs record their project. `ensureActive()` blocks side effects after Cancel or a project switch. The AbortSignal reaches `fetch`, the report captures a snapshot at start, and completed jobs release their closures. **Still open:** moving browser detection to a Web Worker (it currently runs on the main thread). |
| A24 Server AI fields discarded | ✅ | `style`, `wall_color`, `accent_color` and `floor` are each validated and mapped to overrides that take precedence over prompt parsing. The proposal lists which suggestions were applied and which were ignored. |
| A26 Connection test didn't verify the token | ✅ | Health is checked first, then the new protected `/api/auth/check`. Results distinguish unreachable / token rejected / connected-as-user / AI readiness. Default CORS includes `127.0.0.1`. |
| A27 Local env setup | ✅ | `backend/.env` is loaded automatically by uvicorn, Alembic and pytest. There are separate `.env.example` (SQLite, local) and `.env.docker.example` (Postgres, `APP_ENV=production`) files, and Compose uses `.env.docker`. |
| A28 Upload and resource protection | ✅ Partly | Image size is checked **from the file header before decoding** (PNG/JPEG/WebP). Detection runs in a thread pool, limited by `MAX_CONCURRENT_DETECTIONS` (503 with Retry-After when busy). Uploads are deleted after processing and swept after `UPLOAD_RETENTION_HOURS`. Textures are downscaled to 1024 px, and PDFs are opened once and disposed. **Still open:** rate limiting per client, malware scanning, sandboxed parser workers. |
| A29 Capture didn't restore state on failure | ✅ | `try/finally` restores pixel ratio, size and aspect. Context loss is detected, and exports are clamped to `MAX_RENDERBUFFER_SIZE`. |
| A30 PDF text/layout | ✅ Partly | Rows wrap, table headers repeat after page breaks, long titles wrap, and a floor column was added. Characters outside Latin-1 become "?" and **the app warns before export**. **Still open:** embedding a Unicode font for Telugu, Hindi and other scripts. |
| A31 Too many technical decisions | ✅ Partly | Wizard: *Try our sample plan* in one click (with the 12 m line pre-marked), examples of supported and unsupported plans, plain step names, and a **room-naming step** right after detection (the largest room is suggested as Living). Editor: a **Getting started** checklist with one-click actions, and the chat opens by default. **Still open:** an unscaled preview mode and a magnified point picker. |
| A32 Mobile controls | ✅ Partly | Floor selector in the mobile header, **Finish walls / Close room / Cancel** buttons while drawing, **pinch-zoom and two-finger pan** in the plan and in the wizard, touch walkthrough, and the tool strip hides in walk mode. Fixed a bug where `hidden md:inline-flex` buttons were still visible on phones. **Still open:** a true bottom-sheet panel and real iOS/Android device testing. |
| A33 Keyboard / assistive tech | ✅ Partly | Modals render in a portal and trap focus, return focus to the opener, and make the app behind them `inert`. Fields with several controls are `role=group` with a label. Room-naming inputs have labels, and the review step shows status in text as well as colour. **Not claimed:** WCAG conformance; it has not been tested with a screen reader. |
| A34 Performance | ✅ Partly | Edits use **Immer** structural sharing instead of deep-cloning the whole scene on every drag step. The editor and plan subscribe to individual store fields. Shadow maps are smaller on 4-core devices. **Still open:** Web Worker detection, GPU resource disposal audit, code-splitting the PDF library, and profiling on low-end phones. |

## 5. Not covered by this release (needs your sign-off or real-world testing)

1. **Real devices and browsers:** Safari/iOS, Android Chrome, Firefox, low-end phones.
2. **Real customer plans:** build a labelled corpus (open-plan layouts, mixed wall thicknesses, scans, phone photos, diagonal walls) and agree accuracy tolerances before claiming conversion accuracy.
3. **Usability sessions:** 5–8 people who don't use CAD tools, as proposed in the audit. Nothing here claims usability has been proven.
4. **Public multi-user backend:** OIDC/JWT, rate limiting, malware scanning, S3 with signed URLs, backups and monitoring.
5. Remaining open items listed in the tables above (T-junction propagation, furniture collision in walkthrough, Web Worker detection, Unicode PDF fonts, bottom-sheet mobile panel, cloud sync).
